# SOU-16 UI Primitives Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete SOU-16 by extending the design tokens to the full design system, adding the 21 shadcn primitives the ticket specifies, and building the 8 design-system components the design requires but shadcn does not provide.

**Architecture:** Three dependency-ordered layers inside `packages/ui`. Layer 1 is `tokens.css` — every colour, font, radius and shadow the design specifies. Layer 2 is 21 shadcn primitives, generated by the CLI and then remediated for RTL, strict TypeScript, and design geometry. Layer 3 is 8 components that encode product rules (invoice status, exam-prep separation, plan locking). `packages/ui` never imports i18n or domain code; user-facing strings arrive as props with French defaults.

**Tech Stack:** React 19, TypeScript strict, Tailwind CSS v4, shadcn/ui, Radix UI, lucide-react, cva, Vitest + Testing Library (jsdom).

**Spec:** `docs/superpowers/specs/2026-07-29-sou-16-ui-primitives-design.md`

## Global Constraints

- **Package manager is pnpm.** Never npm or yarn.
- **No directional Tailwind utilities.** Use `ps-`/`pe-`/`ms-`/`me-`/`text-start`/`text-end`/`border-s`/`border-e`/`rounded-s`/`rounded-e`/`gap-`. `packages/config/eslint.rtl.mjs` fails the build on `pl-`, `pr-`, `ml-`, `mr-`, `text-left`, `text-right`, `border-l-`, `border-r-`, `rounded-l-`, `rounded-r-`, `space-x-`.
- **No hardcoded user-facing strings in `packages/ui`.** Every visible string is an optional prop with a French default, following `DialogContent.closeLabel`.
- **No `any`, no `@ts-ignore`.** `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, `noPropertyAccessFromIndexSignature` are all on.
- **`import type` for every type-only import** — `verbatimModuleSyntax` requires it.
- **React 19 idioms:** `React.ComponentRef`, not `React.ElementRef`.
- **No literal colours in components.** Reference tokens only. Values live in `tokens.css`.
- **`packages/ui` imports nothing from `@centresoutien/domain`, `react-i18next`, or `apps/`.**
- **Icons:** lucide-react. Meaningful icons take `aria-label`; decorative icons take `aria-hidden="true"`.
- **Commit style:** conventional prefix + `(SOU-16)` suffix. No co-author or session trailers.
- **Branch:** `soufelhanafi/sou-16-react-19-ts-vite-tailwind-shadcnui-setup` (already checked out).

## The remediation pass

Tasks 3, 4 and 5 each generate primitives with `shadcn add` and then apply this
pass. It is written once here because every generated file needs all of it; each
task names the extra work specific to its own components.

Stock shadcn output does not compile or lint in this repo — this is the price of
using the CLI, and skipping any item leaves a broken build or a silently
RTL-broken screen.

1. **Imports** — rewrite `@/lib/utils` to `@ui/lib/utils`.
2. **Direction** — `pl-`→`ps-`, `pr-`→`pe-`, `ml-`→`ms-`, `mr-`→`me-`,
   `text-left`→`text-start`, `text-right`→`text-end`, `border-l`→`border-s`,
   `border-r`→`border-e`, `rounded-l`→`rounded-s`, `rounded-r`→`rounded-e`,
   `space-x-N`→`gap-N`. `pnpm lint` fails on every survivor.
3. **Directional icons** — chevrons and arrows that point sideways get
   `rtl:rotate-180`; icons pinned to an edge use `ms-auto`/`me-auto`, never
   `ml-auto`/`mr-auto`.
4. **Strings** — no hardcoded English. Every user-facing string becomes an
   optional prop with a French default, as `DialogContent.closeLabel` does.
5. **TypeScript strict** — `React.ElementRef` → `React.ComponentRef`; add
   `import type` to type-only imports (`verbatimModuleSyntax`); where a generated
   prop spread trips `exactOptionalPropertyTypes`, destructure the optional prop
   and apply it conditionally rather than casting to `any`.
6. **Geometry** — match the design, not shadcn defaults. Inputs and buttons are
   `rounded-md` (8px); surface cards are `rounded-xl` (12px).
7. **Colour** — no literal hex may survive. Use token utilities (`bg-background`,
   `text-muted-foreground`, `border-input`) or `[var(--token)]` for the
   badge/kind/plan tokens.
8. **Export** — add the component and its prop types to `packages/ui/src/index.ts`.

```ts
import { resolve } from 'node:path';
import { defineConfig, externalizeDepsPlugin } from 'electron-vite';
import react from '@vitejs/plugin-react';
import tailwindcss from '@tailwindcss/vite';

// Three build targets: main + preload (Node/Electron) and renderer (React web).
// externalizeDepsPlugin keeps node_modules (electron, the native SQLCipher
// module) out of the main/preload bundles.
export default defineConfig({
  main: {
    plugins: [externalizeDepsPlugin()],
  },
  preload: {
    plugins: [externalizeDepsPlugin()],
    // Sandboxed preloads must be CommonJS — ESM `import` is rejected at runtime.
    build: {
      rollupOptions: {
        output: { format: 'cjs', entryFileNames: '[name].js' },
      },
    },
  },
  renderer: {
    plugins: [react(), tailwindcss()],
    // @centresoutien/ui ships raw source, so its own `@ui/*` imports resolve here.
    resolve: {
      alias: { '@ui': resolve(__dirname, '../../packages/ui/src') },
    },
  },
});
```

- [ ] **Step 1: Install dependencies**


**`react-hook-form` is a peer dependency, not a dependency.** A second bundled
copy inside `packages/ui` gives `FormProvider` a different React context than the
app's instance, and every `useFormContext()` call silently returns null. The
consumer provides the single RHF instance. `--save-peer` also adds it to
`devDependencies`, which is what makes `pnpm typecheck` work inside the package.

Do **not** add `zod` or `@hookform/resolvers` here. Schemas live in the consuming
app and in `packages/domain`; the UI package only renders fields. `apps/desktop`
already depends on `zod`.

- [ ] **Step 4: Apply the remediation pass**

Apply every item in "The remediation pass" section above to all six generated
files. Two details specific to this task:

- The `ChevronDown` in `SelectTrigger` and the `Check` in `SelectItem` sit at the
  inline end — use `ms-auto`. `SelectTrigger` gains `placeholder?: string`.
- **`FormMessage` takes a deliberate deviation from vanilla shadcn:** it renders
   explicit `children` in preference to the raw React Hook Form message, so the
   app can pass a translated `t()` node while `packages/ui` stays i18n-agnostic.
   Zod schemas in this project emit stable error *codes* rather than sentences,
   and the renderer translates them at display time:

   ```tsx
   export function FormMessage({ className, children, ...props }: FormMessageProps) {
     const { error, formMessageId } = useFormField();
     // Prefer caller-supplied translated content; fall back to RHF's raw message.
     const body = children ?? (error ? String(error.message) : null);
     if (!body) return null;
     return (
       <p id={formMessageId} className={cn('text-sm text-destructive', className)} {...props}>
         {body}
       </p>
     );
   }
   ```

   The `errors.*` i18n namespace itself is out of scope — it lands with the first
   real entity form, not with the primitives.
- Input geometry is `h-9 rounded-md border border-input bg-background px-3 text-sm`,
  matching the design's 8px radius.

```tsx
import { cn } from '@ui/lib/utils';

export type BilingualTextProps = {
  value: string;
  /** `arabic` forces RTL and the Arabic face, even on an LTR page. */
  script: 'latin' | 'arabic';
  className?: string;
};

/**
 * Renders one side of a bilingual field. The design shows `Nom (FR)` beside
 * `الاسم (AR)` in the same LTR table, so the Arabic cell needs its own
 * direction and font rather than inheriting the page's.
 */
export function BilingualText({ value, script, className }: BilingualTextProps) {
  if (script === 'arabic') {
    return (
      <span dir="rtl" className={cn('font-arabic', className)}>
        {value}
      </span>
    );
  }
  return <span className={className}>{value}</span>;
}
```

- [ ] **Step 5: Write `data-table.tsx`**

```tsx
import type { ReactNode } from 'react';
import { cn } from '@ui/lib/utils';

export type DataTableProps = {
  /** CSS track sizes per column, e.g. `['1.3fr', '1.3fr', '120px']` (design 1a). */
  columns: readonly string[];
  children: ReactNode;
  className?: string;
};

/**
 * The design draws tables as CSS grid. We keep the identical geometry via
 * `<colgroup>` on a real `<table>`: grid divs would strip row/column
 * association from screen readers, against the WCAG 2.1 AA target
 * (CLAUDE.md §9). Appearance is unchanged; only the markup differs.
 */
export function DataTable({ columns, children, className }: DataTableProps) {
  return (
    <table className={cn('w-full table-fixed border-collapse text-sm', className)}>
      <colgroup>
        {columns.map((width, index) => (
          <col key={`${width}-${index}`} style={{ width }} />
        ))}
      </colgroup>
      {children}
    </table>
  );
}

export function DataTableRow({ className, children }: { className?: string; children: ReactNode }) {
  return <tr className={cn('border-b border-border last:border-b-0', className)}>{children}</tr>;
}

export function DataTableHead({ className, children }: { className?: string; children: ReactNode }) {
  return (
    <th
      scope="col"
      className={cn(
        'px-4 py-3 text-start text-[11px] font-bold uppercase tracking-wider text-muted-foreground',
        className,
      )}
    >
      {children}
    </th>
  );
}

export function DataTableCell({ className, children }: { className?: string; children: ReactNode }) {
  return <td className={cn('px-4 py-3 text-start align-middle', className)}>{children}</td>;
}
```

`table-fixed` plus `<colgroup>` reproduces the design's `grid-template-columns` proportions: `fr` units become percentage widths, fixed pixel columns stay fixed.
